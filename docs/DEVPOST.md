# SamForGeophysics — Devpost Submission

**Category:** Frankenstein

**Platform:** Desktop web app, Windows 10/11 or Linux, NVIDIA GPU recommended.

---

## Inspiration

Seismic interpreters look for weak deep targets — thin, low-amplitude reflections buried below stronger reflections and noise. These targets carry information about deep geology, but they are often invisible in a standard amplitude display and easy to miss entirely.

Foundation vision models like SAM have been applied to seismic data before: *Seismic Fault SAM* (Chen, Zhang & Ma, [arXiv:2407.14121](https://arxiv.org/abs/2407.14121)) adapts SAM for fault detection with lightweight modules and a 2.5D strategy, and *Domain-Guided Prompting of SAM for Seismic Interpretation* (Ahmad, Bedle & Mustafa, [arXiv:2606.15786](https://arxiv.org/abs/2606.15786)) conditions SAM's input with seismic attributes and colormaps for zero-shot interpretation. Both show SAM can work on seismic sections.

In seismic interpretation, a geophysicist clicking a deep target does not have a ground-truth mask — and on a noisy section, SAM may return something plausible but wrong. We asked: can SAM check its own masks, fix its worst mistakes, and refuse to act when it cannot tell?

## What It Does

A geophysicist opens a synthetic seismic section with a faint deep target in the browser workspace:

1. **Sees it better.** Switch between raw amplitudes and a low-frequency view, or view both side-by-side on synchronized viewports. A single click jumps between noisy and clean recordings of the model.
2. **Prompts SAM3.** Click once on the target and press **▶ SAM**. Slice rendering happens on the server so overlay markers never enter SAM's visual embedding. The mask writes back to a 3-D volume with survey-map footprint tracking.
3. **Lets the loop check the mask.** With Auto-refine enabled, label-free QC evaluates edge leakage and energy capture, generating up to 3 rounds of refinement. Corrective prompts are rendered as hollow diamonds (differentiating automated adjustments from user clicks). Interpreters can click any round in the QC panel to inspect intermediate masks, while the loop keeps the highest-scoring round. If noise overwhelms the target, the QC gate reports why and stops rather than changing the mask.
4. **Exports.** Downloads GeoJSON and CSV polygon contours alongside a JSON log documenting every QC round, corrective coordinate, and score.
5. **Runs without the weights.** The SAM3 model weights are Meta's, under the [SAM License](https://github.com/facebookresearch/sam3), published on Hugging Face ([`facebook/sam3`](https://huggingface.co/facebook/sam3)). Without the SAM3 weights the app still opens; browsing, the low-frequency view, compare and export keep working, with status guidance in the toolbar.

All data is synthetic and generated by a script with a fixed seed. Nothing here has been tested on field data.

## How We Built It

Both **Kiro CLI** and **Kiro IDE** were used. Kiro Web and Kiro Crew were not. The two share one configuration: the specs, steering files and hooks under `/.kiro` are read by both, so the same rules and checks applied everywhere. Kiro IDE was also used (owner statement; no separate log is kept). The CLI ran the agent sessions: spec writing, implementation, test and GPU measurement runs, browser checks and commits. Larger independent jobs were handed to sub-agents with fresh context, some in parallel.

### IDE / CLI / Web / Crew

The CLI drove every build step: spec writing, implementation, test runs, GPU measurements, headless-browser checks and commits. Kiro IDE was also used (owner statement; no separate log is kept). Both share the same `/.kiro` configuration, so hooks and steering apply in either. **Kiro Web and Kiro Crew were not used** — the project was built by one person on a local machine with a LAN GPU, and neither tool offered an advantage over the CLI+IDE combination for this workflow.

### Custom agents

`.kiro/agents/claims-auditor.json` is a read-only reviewer for public text: every number must trace to `docs/MEASUREMENTS.md`, no forbidden claims, SGSeg reuse disclosed, every Kiro claim backed by a file. Run with `kiro-cli chat --agent claims-auditor`. Its first headless run on the README failed it with 7 items, including a wrong start date and two unbacked claims; the run and the fixes are recorded in `docs/kiro/claims-audit-2026-11-12.md`.

### Agent hooks

`.kiro/hooks/dev-loop.json`:
- **PostFileSave** on `src/*.py`: runs that module's tests automatically.
- **PostFileSave** on `src/static/js/*.js`: syntax-checks the frontend scripts.
- **PreToolUse** on the shell: blocks `git add` of data, weights or volume files, `git add --force`, force pushes and `git reset --hard` (exit code 2).
- **Stop**: re-runs the claims check at the end of every agent turn.

Additional hooks: `competition-guards.json` keeps `/.kiro` out of `.gitignore` and rejects forbidden claims when docs change; `data-provenance.json` and `synthetic-data.json` enforce the public-data policy and generator determinism. Tests for the hook scripts and hook files are in `tests/test_hooks.py`.

### Spec-driven development

Three specs in `.kiro/specs/`:
- `samforgeophysics-mvp`: the product spec.
- `qc-refine-loop`: written **before** the code. Its `tasks.md` records what happened when the declared design met data: the first QC design failed its own acceptance criterion (a property test found a counterexample and the ground truth ranked best on 0 of 12 demo checks), the owner chose a redesign, and the spec was changed first, then the code. The measurement protocol was declared in the script before its only run, and its results set two UI defaults.
- `volume-propagation`: written **after** the code, to document and test it.

Compared with prompting feature by feature, the spec made the failure visible: the acceptance criteria were fixed before any result was seen, so a QC that "looked fine" on demo data could not be tuned until it passed.

### Steering

`.kiro/steering/`: `product`, `tech`, `structure`, `competition` and `scope` are always included; `seismic-domain` loads automatically; `sources` (verified prior work) is manual. `scope.md` is the boundary: work that does not map to one of its items is not started, and it holds the convergence rules (no more redesign, one measurement run, the demo story follows the numbers).

### MCP

Not used. The Pencil design MCP was available, but the panels were small enough to design directly in HTML.

### Property-based testing

`hypothesis` tests in `tests/test_qc_service_pbt.py`. They caught a bug the unit tests missed: in the first QC design, *adding* background pixels to an exact mask raised its score (583 of 900 scanned cases), because the envelope spreads target energy past the target's edge. The same tests then defined the redesign's two stated resolution limits.

### Kiro powers

Checked; no power was installed or used.

## Challenges We Ran Into

1. **The first QC design failed its own test.** The spec required the ground truth to rank best among constructed masks. A property-based test found that adding background to an exact mask *raised* its score, and the full acceptance check showed 0 of 12 passes on the demo data. The owner chose a redesign (design C + decision A), and the spec was changed first, then the code.

2. **SAM segmented the UI overlay, not the seismic data.** On the very first in-browser SAM run, the browser embedded a screenshot of the live canvas — including the 6×6 px pick marker. The UI pick produced a 32-pixel marker mask, whereas clean server rendering produced a 521,298-pixel mask (these pixel counts expose the overlay-corruption bug and are not ground-truth target measurements). Fix: a new `/embed` endpoint renders the slice on the server in a clean, uniform integer upscale, so the embedding never contains UI overlays.

3. **The low-frequency view helps interpreters but hurts SAM on noisy data.** On the noisy volume, SAM with one click reaches mean IoU 0.43 on raw but only 0.06 on low-freq. The low-frequency view separates the target by energy but does not help SAM on the noisy volume. The measurement decided the default: SAM and the loop always segment the raw slice, whatever view is displayed.

4. **Clean clone on a second machine exposed five README problems.** A sub-agent that had not seen the repository followed only the README on a fresh LAN machine. It found: the clone needs `-b kiro`, `uv venv` needs `--seed`, torchvision from PyPI replaced the CUDA torch with CPU, `timm` was missing and hung the first SAM call offline, and the SHA-256 check was hard to use. All were fixed in the repository instructions.

5. **The QC loop is not guaranteed to improve.** On 3 of 19 clean-volume slices, the loop kept a round that scored better on QC but worse against the ground truth. This is a known limitation of the label-free QC, recorded in the measurements and the spec, not redesigned.

## Accomplishments That We're Proud Of

All numbers below are on our synthetic model and come from `docs/MEASUREMENTS.md`.

- **Low-frequency separation:** on the noisy volume, the low-frequency view separates the deep target from the background (AUC 0.44 → 0.93), with the model built with a 10 Hz target (script: `scripts/measure_lowfreq.py`). The control footprint (shifted 24 inlines, no target) stays below 0.33, so the filter does not create a target where there is none.

- **QC loop results:** on the clean synthetic volume, raw view (using one simulated include click placed at the interior point of the ground-truth target slice, the pixel farthest from its edge), the label-free QC loop raised the mean IoU of a one-click SAM mask from 0.80 to 0.81 (median 0.88 → 0.89), improving 9 of 19 slices and worsening 3 (script: `scripts/measure_refine.py`). On the noisy volume the loop declined to run on 18 of 19 slices because the target is too weak for the check.

- **The loop checks itself, fixes poor clicks, and never keeps a round with a lower QC score.** The largest gains are slices where the first click gave a poor mask (inline 18: 0.60 → 0.92; inline 23: 0.57 → 0.86).

- **200 tests green**, including property-based tests that found a counterexample to the declared QC design and forced a redesign.

- **Clean clone verified** on a second machine by a sub-agent that had never seen the repository, following the README after obtaining the repository bundle.

## What We Learned

1. **Specs make failures visible.** When acceptance criteria are fixed before any result is seen, a design that "looks fine" on demo data cannot be tuned until it passes. The first QC design failed its own acceptance test, and that failure was the most productive moment of the project — it forced a redesign that was better for clear reasons, not because it happened to work on selected examples.

2. **Measurement as the arbiter.** A result comes from a script with its protocol declared before the first run: fixed data, fixed click rule, fixed metric, run once, reruns byte-identical. Its output, not preference, set the product defaults.

3. **Rules that execute are better than rules that are written.** The hooks run tests on save, block commits of data files, and audit public text for unsourced claims — every constraint that was prose at the start became code by the end, including the `PreToolUse` guard that blocks `git add` of weight files.

4. **People decide, agents build, other agents check.** The owner made the decisions that change meaning (which QC design, which view, what is in scope). Agent sessions implemented and tested. Verification was handed to agents with fresh context — the clean-clone test on the second machine, for example, was done by a session that had never seen the repository.

## What's Next

After the submission deadline, the project's natural next steps are:

- **Field data.** The method is built for synthetic data only. Moving to field data does not change the engineering: declare the metric, run once, report what failed.
- **CPU latency work** to make encoding practical without a GPU.
- **Hosted instance** for access without local setup.
- **Propagation extensions:** negative and box prompts, write locks, low-frequency propagation.
- **Mask management UI, 3-D rendering** beyond the current survey map.
- **Horizon closure error** (deferred; narrowed out of the MVP).
- **Crossline and timeslice polish** beyond what works today.
- **Fault and horizon QC** extending the label-free pattern to other seismic targets.

## What Is New, and What Came Before

This repository started on 2026-11-09 (first commit, `git log`). Part of it comes from **SGSeg**, the author's earlier seismic segmentation tool (begun in June 2026, part of the author's PhD work, solely the author's):

- **From SGSeg:** the slice viewer and its SEG-Y / Zarr / VDS / NumPy loaders, the basic SAM3 embed-and-predict calls and point picking, the first GeoJSON / CSV export, IoU / Dice validation, the LLM assistant, SQLite sessions and local backup.
- **Built in this repository (from 2026-11-09):** the synthetic model and its ground truth; the low-frequency view and the noisy / clean comparison; the measurement scripts; server-side SAM3 rendering; the volume mask, propagation and survey map; the label-free QC, the refine loop, its API, log and panel; the rewritten export with the QC log; the no-weights mode; the English UI; and the whole `/.kiro` workflow.

Prior work on SAM for seismic exists and this project does not claim to be the first: *Seismic Fault SAM* ([arXiv:2407.14121](https://arxiv.org/abs/2407.14121)) and *Domain-Guided Prompting of SAM for Seismic Interpretation* ([arXiv:2606.15786](https://arxiv.org/abs/2606.15786)), which also conditions SAM's input with seismic attributes. What this project adds is the label-free QC loop that decides for itself when it can be trusted, and the noisy / clean pair.

## Testing Instructions

1. Open <http://127.0.0.1:9339>. The noisy volume `synthetic_deep_v1` loads on its middle inline (IL 25). Type `20` in the box next to the direction menu and press **Go** (the box counts from 0; the title then reads IL 21): the deep target is the faint body near the bottom of the section (about 430–510 ms), left of the fault.
2. Press **Low-freq**, then choose **Compare → Raw | Low-freq** to see both. Press **Noisy ⇄ Clean** to jump to the same inline of the clean volume. Set Compare back to **Off** and press **Raw**.
3. On the clean volume, IL 24 (box value `23`): press **Include**, click once in the middle of the deep target, and press **▶ SAM** (Auto-refine is on). The QC panel lists the rounds; click a row to see that round's mask, with the loop's corrective points as hollow diamonds. The survey map shows the mask footprint.
4. Do the same on the noisy volume: the gate stops the loop on most slices of the noisy volume (18 of 19 in the measurement); the panel explains that the target is too weak for the QC on that slice and keeps SAM's mask.
5. Press **Export Mask**: you get `…geojson`, `…csv` and `qc_log_….json`.
6. Optional: **Propagate** extends the mask to neighbouring inlines (settings under ⚙).

For setup instructions (clone, install, data generation, SAM3 weights), see the **Run it** section of the [README](https://github.com/luziqing/seismic-exploration-system#run-it).
