# Guide for development agents

Read this before you touch anything. It is the short version of the rules, the layout and the traps in this repository, current at **2026-11-12, end of M3**. Where it disagrees with `HANDOFF.md`, `CLAUDE.md` or `GEMINI.md`, this guide and `.kiro/steering/scope.md` win; those three files are older.

## 1. What the project is and where it stands

SamForGeophysics is a Kiroween 2026 hackathon entry (Frankenstein category): a local web app that lets an interpreter view a weak deep seismic target in raw and low-frequency views, prompt SAM3, and run a label-free QC loop that refines the mask for up to 3 rounds and exports the result.

- **Deadline:** Fri 2026-12-04 14:00 PT = Sat 12-05 06:00 Beijing. Internal target Thu 12-03. **Feature freeze 11-27**: after that only bug fixes, copy and video.
- **Delivery:** a *test build* (public repo + README instructions). No hosted instance. SAM3 runs on local or LAN GPUs only.
- **Done:** M1, M2, M3 (scope items S1–S10, S13, most of S11; E1, E2, E3, first E6). 200 tests green.
- **Left:** M4 (section 9) and two owner actions: make the repo public; state IDE / Web / Crew use in the README.

The single source of truth for scope and status is **`.kiro/steering/scope.md`, section 0 first**. Work that does not map to an S- or E-item there is not started. Changing the boundary needs the owner's yes, written into `scope.md` first.

## 3. Non-negotiable rules

1. **No invented numbers.** Every result number in public text (README, Devpost text, video, UI copy) must appear in `docs/MEASUREMENTS.md` with the same conditions, printed by a script in `scripts/`. If you need a new number, stop and ask; do not run a new experiment on your own.
2. **Frozen, do not change:** the QC design and its constants (`src/qc_service.py`), the loop constants (`src/refine_service.py`), the measurement protocols in `scripts/measure_lowfreq.py` and `scripts/measure_refine.py`, the H1/H2 metric. A new weakness goes into `docs/MEASUREMENTS.md` or the spec as a limitation. Do not re-run `measure_refine.py` to "improve" results.
3. **UI defaults are decided by the measurement:** SAM and the loop segment the **raw** slice whatever view is displayed; Auto-refine is on for NPY volumes; the UI offers the deep target only (fault QC stays in code and tests).
4. **No "first SAM for seismic"** or any first / only claim. Prior work: `.kiro/steering/sources.md`.
5. **SGSeg is disclosed.** The volume browser, loaders, base SAM pipeline, first export, validation, LLM assistant, SQLite sessions and local backup came from the owner's earlier SGSeg project. Never describe them as new. The README section "Built during Kiroween, and what came before" is the reference.
6. **Data and weights never enter git.** Everything under `data/` is ignored: synthetic volumes (regenerated by script), `data/weights/sam3.pt` (Meta's SAM License), the rules PDF, the DB. Never `git add -f`.
7. **`/.kiro` stays committed** and must never appear in `.gitignore`.
8. **UAV / quantum sensing** are background narrative only, never implemented features.
9. **English only** in the UI, README, docs and Devpost text. The CJK grep in section 6 must stay empty.
10. **Git:** branch `kiro`. No force push, no `git reset --hard`, no rewriting history, no merge into `main` (that is the M4 release step, done by the reviewer). Do not push unless your task says so.

### Working in parallel with other agents

Several agents may share this working tree. Do not edit files outside your task. If your task is large or touches files another agent may edit, use a worktree:

```powershell
git worktree add ..\sfg-<item> -b agent/<item> kiro
cd ..\sfg-<item>
New-Item -ItemType Junction -Path .venv -Target D:\26tmp\soft2-SGSeg\.venv
.venv\Scripts\python.exe scripts/generate_synthetic_seismic.py
.venv\Scripts\python.exe scripts/generate_synthetic_seismic.py --clean
New-Item -ItemType Directory data\weights -Force; New-Item -ItemType HardLink -Path data\weights\sam3.pt -Target D:\26tmp\KiroProject\SamForGeophysics\data\weights\sam3.pt
```

Use another port for your server there (`$env:SAM3_PORT="9340"`).

## 5. Traps that already cost time here

- **`Get-Content` / `Set-Content` corrupt non-ASCII text** on this machine (they read UTF-8 as the ANSI code page). Never round-trip a file through them. Edit with the file tools, or `[IO.File]::ReadAllText` / `WriteAllText($p, $s, (New-Object Text.UTF8Encoding $false))`, or Python with `encoding="utf-8"`.
- `Set-Content -Encoding utf8` and `Add-Content` in PowerShell 5 write a BOM and CRLF. Files here are **UTF-8 without BOM, LF**.
- In PowerShell double-quoted strings the backtick is the escape character, so JavaScript template literals get mangled (`` `$x `` loses the backtick). Put JS/HTML snippets in single-quoted here-strings (`@'...'@`) or use the file tools.
- `Get-ChildItem -Recurse data/npy/*/masks -File` silently returns nothing (wildcard + `-Recurse`). Use explicit paths per volume.
- `certutil`, not `Get-FileHash`, exists in this restricted shell for hashing; on normal PowerShell both work.
- Ultralytics prints warnings to stdout; set `YOLO_VERBOSE=False` in scripts whose stdout must be stable.
- The line box in the toolbar counts from 0 while the title shows IL numbers (index 20 = IL 21). Known, documented in the README, not to be changed now.
- The canvas backing store can differ from its CSS size; map mouse positions with `getBoundingClientRect()` (already fixed in `sgy-client.js`; keep it that way in new code).
- Without `timm` installed, ultralytics pip-installs it at the first SAM call (hangs offline). It is in `requirements.txt` now.

## 7. Code map

**Backend (`src/`, FastAPI):**

| Module | Role |
|---|---|
| `server.py` | All endpoints. NPY: `GET /api/npy/{vol}/slice/{dir}/{i}?mode=raw\|lowfreq`, `POST /embed`, `POST /mask`, `POST /propagate`, `GET /mask/{name}/footprint`, `POST /refine`, `GET /api/refine/{run_id}`; `GET /api/status` (incl. `weights_exists`, `sam_device`, `weights_path`, `weights_source`) |
| `sam_service.py` | SAM3 load (lazy), `embed_image`, `predict_mask_np`; encoding under `torch.inference_mode()` |
| `lowfreq_service.py` | Low-frequency view (`condition_slice`, `lowfreq_timeslice`) |
| `qc_service.py` | Label-free QC: reference envelope at the user's click, leak / miss, score, reliability gate (**frozen**) |
| `refine_service.py` | Loop driver `run()` with injectable segmenter; `attach_truth()` for reporting only (**frozen constants**) |
| `volume_mask_service.py`, `propagation_service.py` | 3-D mask storage and cross-slice propagation (frozen, bug fixes only) |
| `database.py` | SQLite, incl. `refine_runs` / `refine_rounds` with RLE masks |
| `npy_service.py`, `sgy_service.py`, `zarr_service.py`, `vds_service.py`, `llm_service.py`, `validation_service.py` | Inherited from SGSeg: keep working, no new work |

Errors: `ValueError`/`IndexError` → 400, missing → 404, SAM unavailable (`RuntimeError`) → **503** with a message that says what is missing and where to get it. Never let a SAM failure become a 500.

**Frontend (no build step):** `index.html` at the repo root; scripts load in this order: `storage.js`, `canvas.js`, `app.js` (shared globals, `setStatus`, `errText`, `respError`, SAM badge, More menu), `sgy-client.js` (slice loading, picks, navigation), `sam-client.js` (SAM, export), `survey-map.js`, `refine-panel.js` (Auto-refine, QC panel), `compare.js`, `llm-client.js`. Globals are shared across files (`volInfo`, `curDir`, `curIndex`, `sliceMode`, `compareMode`, `logitsMap`, `refineRun`, ...). Slice cache key: `${vol}:${mode}:${dir}:${index}`. Any status text goes through `setStatus(type, msg)` in plain English; fetch errors through `errText(e)` / `respError(resp)`.

**Data:** `scripts/generate_synthetic_seismic.py` writes `data/npy/synthetic_deep_v1` (noisy, 6 dB) and `--clean` → `synthetic_deep_v1_clean` (30 dB), 48 × 48 × 256, seed 20261108, with truth masks in `truth/`. Deep target: inlines 11–29, samples 215–255.

## 10. Before you report back

1. `scripts/verify.py` prints `VERIFY OK`; the CJK check prints nothing.
2. If you touched the frontend: a headless-Chrome run of the affected flow at 1600 × 900 with **no page or console errors** (ignore the favicon 404), and screenshots you have looked at.
3. If you touched SAM, refine or propagation code: the matching e2e script passes against a running server.
4. Test masks you created are deleted; servers you started are stopped (or say which one you left running and on which port).
5. Commit on your branch with a message that names the scope item (e.g. `docs(video): VIDEO_SCRIPT.md (S12)`). Do not push, do not merge.

Then write a report to **`docs/kiro/reports/<item>-<yyyymmdd>.md`** and commit it with your work. The reviewer reads this first:

```markdown
# <item>: <one-line result>
- Branch / commits: ...
- Files changed: ...
- What was done, mapped to the item's "done when" check: ...
- Verification: commands run and their key output (copy, do not paraphrase)
- Numbers used in public text and their line in docs/MEASUREMENTS.md: ...
- Deviations from this guide or the spec, and why: ...
- Open questions for the owner: ...
```

Say plainly what you did not verify. A report that claims a check passed without its output will be sent back.
